Security FAQ

Plain-English security overview for business users.

Discere summarizes emails from contacts you choose. This page explains what the product accesses, what is stored, what is sent to AI, and what risks a business should evaluate before use.

Access

Discere reads relevant mailbox data.

The app searches your connected mailbox for emails from tracked contacts. It does not need you to forward all mail manually, but connected mailbox permissions can technically allow broader access depending on the provider scope.

Storage

Account data and summaries are stored.

Discere stores settings, contacts, schedules, generated summaries, processed message IDs, and limited source email data needed to show summaries and avoid duplicate processing.

What data is read?

  • Gmail: Discere uses Google OAuth to sign you in, read Gmail messages for summarization, and send requested report emails.
  • Microsoft: Discere uses Microsoft OAuth to sign you in, read mailbox content through Microsoft-supported access, refresh tokens, and send requested report emails.
  • Other providers: Discere uses the mailbox credentials or connection settings you provide to read emails from tracked contacts.
  • Contacts filter: The summarizer is designed to process only emails whose actual sender matches your tracked contacts.

What gets sent to AI?

To generate summaries, Discere sends relevant email text and thread context to the AI provider. This can include sender, recipient, subject, message date, body text, and summary preferences.

Attachment contents are sent to AI only if the user enables AI attachment access. If that setting is off, Discere limits attachment use to metadata such as filenames.

What is stored?

Account settings Email address, sign-in method, profile name, preferences, timezone, contacts, and schedules.
Credentials and tokens OAuth tokens or mailbox credentials where needed. These are stored encrypted.
Summary data Generated summary cards, combined reports, done/read state, and limited source data needed to display and manage summaries.
Operational data Analytics events, bug reports, usage counters, and logs used for support, abuse prevention, debugging, and reliability.

How does deletion work?

  • Users can export their account data from Settings.
  • Users can delete individual summaries. This also removes the linked processed IDs so the email can be rediscovered later.
  • Users can delete their account from Settings. This removes account data, summaries, source email files, attachments, schedules, sessions, user analytics, bug reports, and usage counters.
  • Read or done summaries have source email bodies and saved attachments purged after the retention period, while processed message IDs can remain to prevent accidental duplicate summaries.
  • Provider access can also be revoked directly from Google or Microsoft account settings.

Business risk summary

The main realistic risk is that email-derived data is processed and stored by a third-party web application and AI provider. For normal business email, that can be acceptable if users understand the access and retention model. For regulated, attorney-client, medical, financial, export-controlled, or highly confidential data, a business should review its own policies before connecting those inboxes.

Discere uses account isolation, encrypted secret storage, secure production cookies, security headers, rate limits, export/delete flows, and backup procedures. These reduce risk, but they do not make any cloud product risk-free.

OAuth consent screen wording

Google and Microsoft consent screens should describe the app consistently with this behavior:

  • App purpose: Discere summarizes emails from contacts selected by the user.
  • Mailbox read access: Used to find and summarize relevant emails from tracked contacts.
  • Mail send access: Used only when the user requests an emailed report or scheduled report delivery.
  • Profile/email access: Used to sign the user in and identify the connected mailbox.
  • Offline/refresh access: Used to keep scheduled reports and mailbox access working without forcing a new login every run.
